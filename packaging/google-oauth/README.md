### 「安全なフローの使用」の詳細確認（2026-11-11）

Browser Useで警告を展開すると、対象クライアントは「ALTER GENESIS Windows」、具体的な診断は「state パラメータを使用していません」だった。ビルド入力のクライアントIDが対象と一致することを、秘密値を出さずに照合した。PKCE未使用という診断ではなく、WebViewも不使用と表示されている。

現行の`google_auth.rs`はランダムstateとPKCE S256を生成し、`google.rs`はそのURLをブラウザーへ渡す。コールバックはstateが1件かつ一致する場合だけ受け付け、コード交換時にverifierを渡す。既存のOAuth試験3件を再実行し、送信URLのstate・戻り値の照合・不一致後の正しい応答受信がすべて成功した。

対象日時のログイン履歴も値を伏せて照合し、2026-11-10～11のTauriコールバック6件すべてに空でないstateを確認した。直近は11日10:25。近接するGoogle同意画面のクライアントは警告対象と一致した。これは実際の戻り値にstateがあった証拠で、元の認可要求URL自体を記録したものではない。同意画面URLにstateが見えないことを、送信時の欠落の証拠にしない。

**現行フローでstateの欠落は確認されていないが、Google側の警告表示は残っている。** 公式の概要ヘルプでは診断の対象期間・更新所要時間を確認できなかった。旧WPFの利用履歴や反映遅れは原因候補にとどめ、警告が解消したとは扱わない。接続の切断や再認可、クライアント作り直しは行っていない。提出前に診断を再確認し、残る場合は現行の送信内容を追加確認してGoogleへ問い合わせるための材料をそろえる。

根拠は上記ソース、既存`google_auth::tests`、Googleの[概要ヘルプ](https://support.google.com/cloud/answer/15548748?hl=ja#use-secure-flows)と[stateのベストプラクティス](https://developers.google.com/identity/protocols/oauth2/resources/best-practices?hl=ja#use_the_state_parameter)。元の認可コード・state値・ブラウザー履歴全体を提出資料へ添付しない。

### ログイン待ちと撮影の進め方（2026-11-11）

ブラウザーでの操作に時間がかかっても、アプリはログイン全体を10分で打ち切らない。完了、Google側からのエラー、利用者のCancel、アプリ終了で待受を終える。個々のHTTP要求の読取・応答に対する短い期限は、操作待ちとは別に維持する。

もうあるか：アプリに既存のCancellationTokenとCancel操作があるため、それを使う。Tokioの待受FutureはCancel時に破棄され、ローカルのTCP待受も閉じる。別のタイマーや停止機構を追加しない。

手で使う順番は、Connect → ブラウザーで言語・アカウント・権限を選ぶ → 完了してアプリへ戻る。中止する場合はアプリのCancel。撮影では操作ごとに時間制限を設けず、完了の合図で止める。取得した素材と、接続完了まで確認できた動画を区別する。

変更後の確認: 仮想時計を601秒進めた後も待受が続き、正しいcallbackで成功する試験と、待受Futureの破棄でポートが閉じる試験を追加。OAuthの5試験とRustライブラリー全46試験に合格。実Google接続とインストール済み本体での確認は更新後に別途行う。

| 閉じると保存した通知を削除すると説明 | Google通知は重複防止のため`dismissed`を保存 | 即時削除と書かない。同期時の整理と、利用者による全データ削除を説明する |

| カードからGoogleの予定を開けると説明 | 現行Tauriのカードにはそのリンクがない | リンク機能を戻すか、紹介文の該当記述を修正する。審査動画で未実装の操作を見せたことにしない |
| アプリ内のポリシー入口なし | 現行設定画面に公開ポリシーへのリンクなし | 認可前も認可後も到達できる短い入口を用意する |

閉じたGoogle通知は、同期時に通知期限が30日より古いものを整理する実装。停止中・同期しない間も必ず30日以内に消えるという保証にはしない。取得した予定本文の全量や認証値を審査資料へ添付しない。
