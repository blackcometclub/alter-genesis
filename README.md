# 断罪の刻印祭壇（ALTER GENESIS）

Googleカレンダーの予定を、ユーザーが自分で閉じるまで残る通知パネルで知らせるWindowsアプリ。

カレンダーの代わりを作るのではなく、「予定を見落とさない」ことだけに特化する。

## 現在地

- 初版は読み上げなしの通常版
- 通知には開始時刻と予定名を大きく表示
- 左側にGoogleカレンダーの色を使った、意図的に幅の広い帯を置く
- 再通知と閉じる操作だけを小さく置く
- 複数の通知は一つのウィンドウ内で縦に積む
- 長い予定名は1行で省略し、暗い角丸のツールチップで全文を表示
- 主文字は `#DBDBDB`。ホバーでも白へ戻さない
- 通知音は「なし／ころん／きらり／ぴこん」から選択し、試聴・保存できる
- 通知音の鳴り直しは「なし／1分／3分／5分／10分」から選び、カードが残る間だけ繰り返す
- カードの大きさは「小さめ／大きめ」の2種類から選択・保存できる
- 再通知の5分・10分・30分・1時間を実行し、予約と表示中の通知を保存する
- Googleログインで選んだカレンダーを読み、Googleに設定した画面通知の時刻にカードを出す
- Google接続中は最後の取得完了から5分後に自動で再取得する
- Googleの終日予定はWindowsのローカル時間で当日9:00に知らせ、カードには「終日」と表示する
- 設定から現在のWindowsユーザーのサインイン時に自動起動できる
- WPF + C# のダミー通知プローブを実装中

詳しい判断は [設計検討メモ.md](./設計検討メモ.md) と [手動操作順.md](./手動操作順.md) を参照。

Googleで設定した個別の通知時間を読むため、通常版と独立した[OAuth通知時刻の読み取り実験](./experiments/AlterGenesis.GoogleReminderProbe/README.md)を追加した。この実験はJSONの選択を不要にし、通知設定の取得と時刻計算だけを行う。その結果を開発者が一度だけ隔離したWPFへ渡す実時間試験でも、予定の2分前のカード表示と通知音を確認した。この確認を踏まえ、Googleの読取結果をWPFの通知予約へ自動で渡す処理を追加した。

2026-10-29、今後の通常版はGoogleログイン方式を本線にする方針へ更新した。GoogleとALTER GENESISの両方で通知時刻を設定する二度手間を避けるため。一般配布の準備は開発側で行い、利用者にGoogle Cloud設定やJSON選択を求めない。現在はテスト利用者向けの検証段階。通常版への取得連携と5分ごとの定期取得を実装したが、一般配布の準備は未完了。既存iCal実装・保存データは比較資産として保持する。

## WPFプローブの起動

Windowsと.NET SDK 8以降、.NET 8 Desktop Runtimeを使用する。プロジェクトのルートで実行する。

```powershell
dotnet build .\AlterGenesis.sln --configuration Debug
dotnet run --project .\src\AlterGenesis.NotificationProbe --no-build -- --single --inspect --lang=ja
dotnet run --project .\src\AlterGenesis.NotificationProbe --no-build -- --settings --lang=ja --data-dir=artifacts/my-sound-preview
```

- 初回起動: Googleの接続設定を開く。保存済み認証があればブラウザーを開かず復元し、選択したカレンダーを取得する。ダミー通知は「通知を試す」で追加する。`--single` / `--many` はダミー通知の件数指定。
- `--lang=ja` / `--lang=en`: 開発時の表示確認用上書き。通常利用では設定の「言語」を使う。予定名は翻訳しない。
- `--inspect`: 確認用にタスクバーへ表示してアクティブにする。通常はタスクバー非表示でフォーカスを奪わず出す。
- `--settings`: 言語・カードの大きさ・通知音・鳴り直しの設定で起動する。通知パネルの右クリック →「設定」からも開ける。
- `--startup`: Windowsの自動起動から使う内部指定。通常起動と同じ動作をし、すでに同じ保存先のALTER GENESISが動いていれば警告を出さず終了する。
- `--data-dir=artifacts/my-sound-preview`: 設定と通知の保存先を分離する。選択は `settings.json`、Google通知は `google-notifications/notifications.json` へ保存する。省略時は `%LOCALAPPDATA%/TINMOON/AlterGenesis.NotificationProbe/`。この保存先を使うプロセスの二重起動をアプリ固有のキーで防ぐ。
- `--layout-report=artifacts/layout.json`: 描画後に色帯・文字・操作部品の寸法をJSONへ記録し、合否を終了コードで返す。同じ名前のPNGへWPFの描画を保存する。空白を含む絶対パスではなく、上記の相対パスを推奨。
- `--card-size=small` / `--card-size=large`: 配置診断で使うサイズ。省略時はsmall。通常起動では保存された選択を使う。
- `--resize-report=artifacts/card-resize.json`: 表示済みの同じ通知を大→小→1件閉じる→大→小と切り替え、幅・高さ・通知の保持を計測する。実設定・音は使わず、各段階の描画もPNGへ保存する。
- `--settings-layout-report=artifacts/settings-layout.json`: 設定画面の描画後に操作部品の高さ・上下端・右端を測る。`--data-dir` と言語を併せて指定できる。
- `--calendar-add-layout-report=artifacts/calendar-add.json`: iCal追加画面の描画と操作高さを確認する。`--calendar-add-step=details` を併せると名前・色の段階を確認する。
- `--ical-report=artifacts/ical-checks.json`: 隔離した偽URLと偽応答だけで、秘密URLの暗号化保存、不正データ保護、繰り返し・終日・取消の展開、安定IDと重複防止、開始待ちの保存、接続エラー分類、URL制限を検証する。実際のGoogle予定や秘密URLは使わない。
- `--sound-report=artifacts/sound-checks.json`: 同じ `artifacts` 内の新しい隔離フォルダで、設定保存・不正ファイル保護・再生回数・失敗時の継続・埋め込みWAVを検証する。実際の音や実設定は使わない。
- `--snooze-report=artifacts/snooze-checks.json`: 隔離した保存先と検証用時計で、再通知の期限、保存・再読込、同時通知、保存失敗、不正データ保護を試す。実際の音や実設定は使わない。
- `--startup-report=artifacts/startup-checks.json`: メモリ上の偽ショートカットで、実行パスを含む追加・読取・置換・削除と失敗時の保護を試す。さらに報告先の隣に実 `.lnk` を一時作成して内容を読み、削除する。Windowsの実スタートアップフォルダーは変更しない。
- `--runtime-report=artifacts/runtime.json`: 実プロセスで通知が表示されたあとに状態と配置・PNGを記録して終了する。`--data-dir` の明示指定が必須。保存済み予約からの待機・表示・再起動の検証用。

## カードの大きさ

| 大きさ | 幅 | 単独通知の高さ | 複数件の最大高さ |
| --- | ---: | ---: | ---: |
| 小さめ | 376 | 131 | 514 |
| 大きめ | 560 | 155 | 602 |

数値はDIP。小さめの横幅は大きめの約2/3、単独カードの面積は約43%小さい。時刻28、予定名26、色帯40、操作部品32は両方共通で、幅と余白を変える。

設定の「カードの大きさ」で切り替えると、表示中の同じ通知ウィンドウへ反映する。閉じた通知を戻したり、音を鳴らし直したりしない。通知音と一緒に保存する。新規設定の初期値は小さめ。サイズの項目がない以前の設定は、音の選択と従来の大きめを保持して読み込む。

## 表示言語

設定の先頭で「システム」「English」「日本語」を選ぶ。保存・適用ボタンはなく、選択すると設定画面、表示中の通知カード、トレイメニュー、Google接続状態へその場で反映し、次回起動にも保持する。「システム」はWindowsのUI言語が日本語なら日本語、それ以外は英語を使う。予定名とカレンダー名は利用者のデータなので翻訳しない。以前の設定JSONに言語がなければ「システム」として読む。

## 通知音

初期値は「ころん」。選択すると保存し、再起動後も保つ。音を選ぶだけでは鳴らさず「試聴」で鳴らす。「なし」では試聴を無効にする。「通知を試す」はダミー予定を表示する。

通知パネルを描画したあと、同時に表示した予定の件数によらず1回だけ鳴らす。既存の通知を閉じたり、スクロールしたりしても鳴らし直さない。音の失敗でパネルは閉じない。連打した試聴は前の音を置き換え、音を重ねない。

「鳴り直し」は初期値「なし」。1分・3分・5分・10分から選ぶと、カードが一枚でも表示されている間だけ一周期に1回鳴る。複数カードでも一度に複数回は鳴らさない。新しい通知が最初の音を鳴らした時点から数え直し、すべてのカードを閉じるか再通知へ送ると止まる。「試聴」だけでは開始せず、通知音「なし」でも開始しない。設定項目のない以前のJSONは「なし」として読む。

WAV原本は `audio/candidates/2026-10-28/` に保持し、ビルド時にアプリへ埋め込む。再生は `INotificationEffect` から分離した処理で行い、将来の音声を後付けできる。非同期のWAV再生にはWindowsの [PlaySound](https://learn.microsoft.com/en-us/previous-versions/dd743680(v=vs.85)) を使う。再生用メモリは停止まで保持し、ファイル不足時の代替システム音は使わない。

設定は一時ファイルへ書いてから置換する。読めない・壊れた・新しい形式の設定ファイルは上書きせず、無音で起動し、変更時にエラーを伝える。確認では `artifacts` 内の隔離した保存先だけを使った。CodexのMSIX環境から起動した場合の既定AppDataへの保存を、外部からの配置確認済みとは扱わない。

## Googleログインと通知設定

設定の「Googleでログイン」からブラウザーで読み取りを許可し、通知したいカレンダーへチェックする。ログイン情報とカレンダー選択は `google/*.dpapi` にWindowsの現在ユーザーで暗号化保存する。ログイン済みなら起動時にそのまま復元する。失効時の再ログインは利用者がボタンを押したときだけ行う。

取得タイミングは起動・接続・チェック変更・手動の「更新」と、最後の取得完了から5分後。取得中に次の処理を重ねず、手動操作が完了した場合もそこから5分を数え直す。失敗時は前回の完全な予約を残し、接続が有効なら次の5分周期で再試行する。切断すると停止する。時刻付き予定は個別のpopup通知を優先し、`useDefault` の予定には毎回読み直したカレンダー既定通知を使う。「通知なし」は通知せず、メール通知はカードへ変換しない。

終日予定はGoogleの通知分数を再現したとは扱わず、ALTER GENESIS自身の固定規則としてWindowsのローカル時間で当日9:00に通知する。Google APIから開始日だけを読み、カードの時刻欄は「終日」。設定項目は増やさない。初めて取得した時点で9:00を過ぎている当日予定は遅れて新規表示せず、以前から保存済みの予約がアプリ停止中に期限を過ぎた場合だけ、既存の期限超過処理で次回起動時に表示する。

通知時刻が今後30日以内になる予定を対象にする。最大4週間前の通知を落とさないよう、予定の開始は58日先まで取得する。繰り返しはGoogle側で各回へ展開する。予定名で絞らず、全ページを読み終えた時だけ予約を更新する。予定や通知時刻の変更・取消は次の取得で反映し、取得失敗時は前回の予約を残す。未確認のカードと再通知待ちは更新で消さず、チェック解除したカレンダーは予約・カードを停止する。

カレンダー・予定・開始回・通知分数から安定IDを作る。過去の通知は新規に取り込まず、閉じたカードを再取得で復活させない。すでに保存済みの期限切れ予約は直近30日以内の取得範囲で照合し、現在も有効なら起動時に表示する。取得中は期限判定を待ち、保存に失敗した予約を部分的に入れ替えない。予約が空でもトレイに残り、設定と終了を開ける。

Google側のカレンダー色を帯に使い、予定名からGoogleが返したHTTPSの予定リンクを開く。カードの大きさ・文字・ツールチップ・再通知・音は既存のものを使う。

## Windowsと一緒に起動

設定の「Windowsと一緒に起動」は、選んだその場で現在のWindowsユーザーのスタートアップフォルダーに `ALTER GENESIS.lnk` を作成・削除する。適用ボタンや説明文は置かない。管理者権限やレジストリを使わず、ほかのアプリのショートカットには触れない。ショートカットには現在のALTER GENESIS本体の絶対パス、内部指定 `--startup`、本体の作業フォルダーを保存する。設定を開くたびに保存設定ではなくショートカットの実体と内容を読む。

サインイン時も通常版としてGoogle接続・予約・トレイ待機を復元する。同じ保存先のALTER GENESISがすでに動いている場合、自動起動側だけ静かに終了する。配布時はインストール後の安定した場所にある本体から有効にする。移動・削除され得る開発用ビルドは製品の自動起動へ登録しない。

開発確認で `--data-dir` を明示している場合だけ、その保存先を絶対パスに直して自動起動へ引き継ぐ。Windowsのサインイン時には作業フォルダーが保証されないため、相対パスのまま登録しない。通常利用の既定保存先では追加引数を付けない。

開発者がデスクトップ用クライアント設定をビルド時に埋め込む。既定の入力はGit除外の `artifacts/oauth-reminder-build/client.json`（`ClientId` / `ClientSecret`）で、`-p:GoogleClientFile=...` でも指定できる。認証トークンは埋め込まない。入力がないビルドでも自動試験は可能だが、ログインはできない。利用者へJSONを選ばせない。現在のGoogleプロジェクトはテストユーザー向けであり、生成したEXEは一般配布用ではない。一般公開・審査・公開文書はまだ準備していない。

- `--google-report=artifacts/google-checks.json`: 偽Google応答と検証時計で、通知時刻・複数通知・変更取消・閉じた後の再取得・保存失敗・ページ取得失敗などを検証する。
- 起動時にファイアウォールが最初の通信を拒否した場合は、許可操作を待ちながら2秒・5秒・10秒・15秒後に自動再試行する。通常の手動更新や認可エラーにはこの待機を広げない。
- `--google-state-report=artifacts/google-state.json`: 件数・状態・失敗の種類だけを記録する。`--data-dir` 必須。予定名、カレンダーID、秘密情報、例外本文は記録しない。
- `--google-settings-report=artifacts/google-settings.json`: 起動時の接続復元後に設定画面の配置JSON/PNGを保存する。`--settings` と `--data-dir` を併用する。
- `--ical`: 以前のiCal版を比較検証するための開発用起動。通常画面に接続方式の選択は出さない。iCal登録 `calendars.dpapi` と旧予約 `notifications.json` は削除・変換せず保持し、この指定があるときだけ使う。GoogleとiCalの取得処理を同時には動かさない。

### 統合の検証（2026-10-29〜30）

- Debugビルドは警告0・エラー0。Googleの隔離検証21件に合格。既定/個別/通知なし、複数通知、変更取消、ページ途中の失敗、保存失敗、通信失敗時の選択保持、再起動後のチェック解除反映、ファイアウォール許可待ちからの復帰を含む。認証情報や実予定を使わない試験である。
- 既存のiCal21件、再通知19件、通知音16件、カードの大小往復も合格。日本語・英語の設定画面のWPF描画計測は共通操作高さ32 DIP、行の上下端の差0。
- 実Googleから選択した1カレンダーを取得し、開始20:20・個別popup 2分前の予定を20:18に表示状態へ移行。開発者による予約JSONへの手渡しは行っていない。ユーザーの実画面画像でカードを確認し、通知音「ころん」も「聞こえた」と回答を得た。画像内の20:06は前のテストから閉じずに残していたカード。

## 旧iCal接続（`--ical` での比較用）

設定の「Googleカレンダー」から「追加」を押し、Googleカレンダーの「設定と共有」→「カレンダーの統合」にある「iCal形式の非公開URL」を貼り付ける。取得した名前を確認し、通知の太い帯に使う色を選ぶ。Google側の色はiCalから取得できないため、色はALTER GENESIS内だけの設定になる。

非公開URLは、それを知る人が予定を読める秘密情報である。入力時以外は画面に戻さず、ログや診断ファイルにも書かない。保存ファイル `calendars.dpapi` はWindows DPAPIのCurrentUserで暗号化し、現在のWindowsユーザーだけが復号できる。壊れた・別ユーザーのデータは上書きしない。取得先はHTTPSの `calendar.google.com` に限定し、自動転送を追わず、20秒・5 MiBを上限とする。

通常起動時に登録済みカレンダーを一度取得し、現在から30日以内の時刻付き予定と繰り返し予定を開始待ちへ保存する。終日予定はその日の9:00に通知し、カードの時刻欄には「終日」と表示する。取り消された予定は除外する。カレンダー・予定UID・開始回から安定IDを作るため、同じフィードを開き直しても増えない。取得に成功したカレンダーだけ開始待ちを最新状態へ入れ替え、通信に失敗したカレンダーの以前の待ちは消さない。

設定の「iCalから再取得」を押すと、アプリを起動し直さずに登録済みの全カレンダーを一度取り込み直す。各カレンダー行の「接続確認」は、保存済みURLで接続と名前を確かめる操作として分ける。取得中の二重操作を防ぎ、成功・失敗はボタンと同じ行へ短く表示する。定期取得はまだ行わないため、Googleカレンダーへ追加・変更した予定を自動で追い続けるものではない。この段落は保持している旧iCal経路を説明する。通常起動は上記のGoogleログインを使う。
