# ALTER GENESIS — Tauri製品版候補

> [!IMPORTANT]
> Tauri 2 + Rust + Svelteを、次の製品版の実装基盤として採用した。まだ移植中であり、一般利用者向け完成版ではない。

Googleカレンダーの選んだ予定を、ユーザーが確認して閉じるまで残る独自パネルで知らせるWindowsアプリ。

## 現在の範囲

- Tauri 2 + Svelte + TypeScript
- Rust製のデスクトップ本体
- 言語、カード大小、通知音、鳴り直しだけに絞った設定画面
- Svelteの4項目をRust側の設定保存へ接続。画面側には別の保存状態を持たせない
- 言語変更時に画面文言とウィンドウタイトルを即時更新
- 壊れた設定と新しい形式は上書きせず保護する
- 開発時だけ`ALTER_GENESIS_SETTINGS_PATH`で隔離設定ファイルを指定できる
- Rustが持つ通知状態から、到達した通知カードを一つのパネルに並べて表示する
- 小さめ376×130／大きめ560×154、40pxのカレンダー色帯、大きな時刻と予定名

WPF版で確認済みのGoogle接続、通知時刻計算、カード、音、鳴り直し、トレイ、保存、自動起動を一度に作り直さず、操作単位ごとに移植する。WPF版は比較と回帰確認のために残す。

旧い初回設定モック、偽のGoogle接続、テスト通知ボタンは製品画面から外した。通知カードの表示・閉じる、「5分後に再通知」と終了・再起動をまたぐ保存・復元、通知音の試聴・表示時の再生・表示中だけの繰り返しを移植済み。Googleログイン、一覧と選択の保存に加え、選んだカレンダーの実予定と通知設定の取得を追加した。

## Googleの通知時刻で知らせる

時刻付きの予定は、予定の`reminders.useDefault`がtrueならカレンダーの`defaultReminders`、falseなら予定の`overrides`からpopup通知だけを使う。通知なし・メールだけの予定へ独自の通知時刻を足さない。同じ分数の重複は一回にまとめ、異なる分数の通知はそれぞれ予約する。自己の出欠がdeclinedの予定と取消済みの予定は除く。

終日予定は利用者の明示した別ルールに従い、その日、PCのローカル時刻の朝9時に知らせる。Google画面の終日専用通知時刻を再現する機能ではない。曖昧または存在しないローカル日時を推測で補わず、取得失敗として前の予約を保持する。

もうあるか：Google公式の[通知設定](https://developers.google.com/workspace/calendar/api/concepts/reminders)、[Events.list](https://developers.google.com/workspace/calendar/api/v3/reference/events/list)、既存WPFの取得・予約処理を確認。繰り返し予定の展開はGoogleの`singleEvents`を使い、日時は既存依存のchrono、安定IDはsha2を利用する。サーバーやOSへの通知予約登録は追加しない。

予定の取得は起動・接続・選択変更・手動更新と5分ごと。現在から30日以内の通知を対象に、4週間前の通知も落とさないよう開始58日先まで読み、全ページ/全対象カレンダーを取得できた時だけ未来の予約を入れ替える。保存済みの期限切れ予約は直近30日の範囲で照合する。新しく読んだ過去の通知は作らず、過去に予約した分だけ起動後に追いつく。取得失敗時は前の予約を使う。選択を変える場合は進行中の通信を取り消し、新しい選択で取り直す。

実予定の状態は設定と同じディレクトリの`google-notifications.dpapi`へ暗号化保存する。独立したファイルロックと、書込み・同期・置換が成功した後だけの状態変更で保護する。壊れたデータは上書きしない。旧プレビューの`notifications.json`は読み替え・移行しない。予約・表示中・再通知待ち・閉じた履歴を保存し、未確認と再通知待ちは一覧更新で勝手に消さない。チェック解除は対象カレンダーの予約/表示を止め、再選択でも閉じた通知を戻さない。閉じた履歴は30日保持する。

一秒ごとの期限比較で到達した分を、同じ通知パネルへ並べる。音は一周期に一回。各カードを閉じる/5分後に再通知でき、全件が消えたらパネルと鳴り直しを止める。カードの明示操作は通信待ちを待たずに保存する。待機中は予定全体の毎秒コピーや保存をせず、期限に到達した時だけ表示状態へ書き換える。

Googleへの要求権限は一覧と予定の読取りのみ。以前の一覧専用接続には再接続を案内し、利用者がGoogle上で追加の参照を許可する。アプリの終了中は通知せず、次の起動で保存した状態と取得結果を使う。現在は設定窓を閉じるとアプリが終了する。Tauriのトレイ常駐とWindows自動起動は後続の移植単位。

## Googleログインとカレンダー一覧

「接続」で既定ブラウザーを開き、利用者がGoogleアカウントを選んでカレンダー一覧と予定の参照を許可する。取得したカレンダー名と色を設定画面へ表示する。「更新」で一覧を取り直し、取得に失敗した場合は前回の一覧を残す。起動時は保存済みの一覧を復元し、ログイン画面を自動で開かない。

一覧のチェックか名前を押すと、そのカレンダーの通知対象の選択を保存する。初期状態は全件オフで、全件オフのまま保存することもできる。保存成功後だけ画面のチェックを変え、失敗したら元の状態を残す。保存中は一覧更新と別の選択を止め、一覧の通信中も選択を変更できない。選択を保存した後、対象の予定と通知設定を取得して予約する。

一覧更新では同じIDの選択を保持し、新しいカレンダーを自動で選ばない。全ページ取得に成功して一覧から消えたIDは対象から外す。再接続では主カレンダーIDが同じ場合だけ選択を引き継ぎ、別アカウントや識別できない場合は空選択にする。選択は接続と同じ暗号化ファイル内の`selected_ids`へ保存する。既存の形式1でこの項目がない場合は空選択として読み、最初の書換え前に暗号化原本を`google.dpapi.before-selection.bak`へ保存する。異なる既存控えがあれば上書きせず保存を止める。旧版は追加項目のあるファイルを既存の保護処理で拒否するため、控えも保持する。「切断」はこの控えも削除する。

## 5分後に再通知

カードの「5分後に再通知」で同じ窓を隠し、Rust側の状態とTokioタイマーで300秒後に同じカードを一度だけ戻す。二重操作・別ID・期限前・古いタイマー・取消後の復活を拒否する。予定の開始時刻は変えない。日本語・英語のボタンは既存の共通高さ32pxへそろえる。

通知と再通知の期限は設定ファイルと同じ専用ディレクトリの`notifications.json`へ保存する。期限前に起動し直すと残り時間を待ち、終了中に期限を過ぎた場合は起動時に表示する。表示中のカードも復元し、閉じたカードは復活しない。アプリ終了中に通知を表示する機能ではなく、次に起動したときの復元を扱う。

Rustが状態を所有し、再通知・閉じるの操作は一時ファイルへの書込み・同期・置換が成功してから状態を変える。保存に失敗した場合はカードを残し、操作エラーを表示する。壊れたJSON・新しい形式・欠けた必須項目は上書きせず、設定画面にエラーを出して変更を止める。保存済みの空状態と初回起動を区別し、`--notification-preview`でも閉じたサンプルを勝手に作り直さない。

同じ保存先の通知を二重に変更しないよう、別の`notifications.lock`をOSのファイルロックで保持する。終了するとロックは解放される。設定と通知ファイルは独立し、WPFの保存先へは書き込まない。`ALTER_GENESIS_SETTINGS_PATH`指定時はその親ディレクトリを通知の保存先にも使う。

再通知を表示に戻すときは、期限を消して表示中の記録へ更新する。この更新に失敗しても期限切れのカードの表示は止めず、元の保存内容を保つ。

保存時刻にはUTCのepochミリ秒を使い、待機中は1秒以内の間隔で期限を読み直す。OSの時計変更や休止後も、保存した期限より前に表示しない。残った書込み途中の一時ファイルは上書きせず、次の保存には別名を使う。通知JSONは暗号化していない。

保存・復元の自動検証：Rust13試験、整形、Clippy、Svelte0エラー/0警告。期限前の再起動、期限切れと表示中の復元、閉じた通知の不再表示、保存失敗時の保持、破損・将来形式の保護、二重起動ロック、時計の前後移動を確認。静的検査・自動試験・Releaseビルドは実画面確認前に実施し、容量整理後の再ビルドは行っていない。

起動中の再通知の検証（2026-11-10）：Rust12試験、整形、Clippy合格、Svelte0エラー/0警告、Tauri Releaseビルド成功。Small・日本語の実画面で32pxの二つのボタンが収まり、「5分後に再通知」で窓が隠れることを確認。短縮せず5分待ち、同じ窓IDに同じ予定一枚が戻ることと、カード内の「閉じる」で終了することを確認した。English・Largeの実画面、再起動復元、音は今回の確認対象外。

もうあるか：Tauriの非同期ランタイムと、依存済みTokioのsleepを利用する。独自の待機スレッドや画面側の別タイマーは作らない。[Tauri spawn](https://docs.rs/tauri/latest/tauri/async_runtime/fn.spawn.html)、[Tokio sleep](https://docs.rs/tokio/latest/tokio/time/fn.sleep.html)。

## 通知音

WPF版で採用済みの「ころん」「きらり」「ぴこん」を原本のまま埋め込む。設定で選んだ音を隣の「試聴」で鳴らす。「なし」では鳴らさず、試聴ボタンを無効にする。選択は既存の設定ファイルへ保存する。

新しい通知と再通知の表示後に一度鳴り、表示中だけ「音の繰り返し」の1／3／5／10分間隔で鳴る。試聴だけでは反復予約を作らない。すでに表示していたカードを起動時に復元するときは初回音を重ねず、繰り返しの待機だけを始める。再通知で隠れている間と閉じた後は停止する。音と繰り返しの設定を変えると、それまでの再生を止めて現在時刻から数え直す。時計の前進や休止復帰で間隔を飛び越えても、取りこぼした回数をまとめて鳴らさない。

Rustが再生と反復期限を所有し、通知の表示状態はNotificationStateから読む。再生に失敗しても通知カードを消したり、再通知の復帰を止めたりしない。試聴の失敗は設定画面に表示する。

もうあるか：Windows標準の[PlaySound](https://learn.microsoft.com/en-us/previous-versions/dd743680(v=vs.85))とWPF版の実装を確認して採用した。Rustは依存済みwindows-sys 0.61.2の音声機能を使用。短いPCM音3つには別の再生ライブラリは不要だった。SND_MEMORY／SND_ASYNC／SND_NODEFAULTで埋込バッファを非同期再生し、バッファはstaticとして保持。再生の停止は同じプロセスの音に限り、Windowsの設定やレジストリは変更しない。

通知音の自動検証（2026-11-10）：既存の保存・復元を含むRust18試験、fmt、Clippyに合格。Svelte検査は0エラー/0警告。内蔵画面を使うReleaseビルドに成功。直接Cargoで実行用ビルドを作る場合は、Tauri CLIと同様に`--features tauri/custom-protocol`を指定する。指定がない直接ビルドは開発URLを選ぶため、この確認では使わない。

通知音の隔離実画面（2026-11-10）：日本語・英語で選択欄と試聴ボタンが同じ高さに収まり、Noneで試聴が無効になることを確認。3音を順に試聴し、利用者が3つとも聞こえたことを確認した。新規カードの音声API成功1回、実時間1分後に追加1回、再通知で隠した後は1分以上追加0回。別の20秒の保存予約fixtureでは、期限前0回・期限後1回（Kirari）とカード復元、閉じた後の空保存を確認した。API成功の計数と、利用者による試聴の受け入れは区別する。確認用Tauriは全終了、日常WPFは維持、Computer Useは各確認直後に終了した。

## 責任の分け方

- Rust: 設定と通知状態の保存、Google接続、予定取得、時刻計算、鳴り直し、トレイ、単一起動、自動起動ショートカット。
