# ALTER GENESIS — Tauri製品版候補

> [!IMPORTANT]
> Tauri 2 + Rust + Svelteを、次の製品版の実装基盤として採用した。まだ移植中であり、一般利用者向け完成版ではない。

Googleカレンダーの選んだ予定を、ユーザーが確認して閉じるまで残る独自パネルで知らせるWindowsアプリ。

## 現在の範囲

- Tauri 2 + Svelte + TypeScript
- Rust製のデスクトップ本体
- 言語、カード大小、通知音、鳴り直しだけに絞った設定画面
- Svelteの4項目をRust側の設定保存へ接続。画面側には別の保存状態を持たせない
- 言語変更時に画面文言とウィンドウタイトルを即時更新
- 壊れた設定と新しい形式は上書きせず保護する
- 開発時だけ`ALTER_GENESIS_SETTINGS_PATH`で隔離設定ファイルを指定できる
- Rustが持つ通知状態から、独立した通知カードを1枚だけ表示して閉じる
- 小さめ376×130／大きめ560×154、40pxのカレンダー色帯、大きな時刻と予定名

WPF版で確認済みのGoogle接続、通知時刻計算、カード、音、鳴り直し、トレイ、保存、自動起動を一度に作り直さず、操作単位ごとに移植する。WPF版は比較と回帰確認のために残す。

旧い初回設定モック、偽のGoogle接続、テスト通知ボタンは製品画面から外した。通知カード一枚の表示・閉じる、「5分後に再通知」と終了・再起動をまたぐ保存・復元を移植済み。Google接続、予定の通知時刻計算、音はまだTauri版へ移植していない。

## 5分後に再通知

カードの「5分後に再通知」で同じ窓を隠し、Rust側の状態とTokioタイマーで300秒後に同じカードを一度だけ戻す。二重操作・別ID・期限前・古いタイマー・取消後の復活を拒否する。予定の開始時刻は変えない。日本語・英語のボタンは既存の共通高さ32pxへそろえる。

通知と再通知の期限は設定ファイルと同じ専用ディレクトリの`notifications.json`へ保存する。期限前に起動し直すと残り時間を待ち、終了中に期限を過ぎた場合は起動時に表示する。表示中のカードも復元し、閉じたカードは復活しない。アプリ終了中に通知を表示する機能ではなく、次に起動したときの復元を扱う。

Rustが状態を所有し、一時ファイルへの書込み・同期・置換が成功してから状態を変える。保存に失敗した場合はカードを残し、操作エラーを表示する。壊れたJSON・新しい形式・欠けた必須項目は上書きせず、設定画面にエラーを出して変更を止める。保存済みの空状態と初回起動を区別し、`--notification-preview`でも閉じたサンプルを勝手に作り直さない。

同じ保存先の通知を二重に変更しないよう、別の`notifications.lock`をOSのファイルロックで保持する。終了するとロックは解放される。設定と通知ファイルは独立し、WPFの保存先へは書き込まない。`ALTER_GENESIS_SETTINGS_PATH`指定時はその親ディレクトリを通知の保存先にも使う。

保存時刻にはUTCのepochミリ秒を使い、待機中は1秒以内の間隔で期限を読み直す。OSの時計変更や休止後も、保存した期限より前に表示しない。残った書込み途中の一時ファイルは上書きせず、次の保存には別名を使う。通知JSONは暗号化していない。

保存・復元の自動検証：Rust13試験、整形、Clippy、Svelte0エラー/0警告。期限前の再起動、期限切れと表示中の復元、閉じた通知の不再表示、保存失敗時の保持、破損・将来形式の保護、二重起動ロック、時計の前後移動を確認。静的検査・自動試験・Releaseビルドは実画面確認前に実施し、容量整理後の再ビルドは行っていない。

起動中の再通知の検証（2026-11-10）：Rust12試験、整形、Clippy合格、Svelte0エラー/0警告、Tauri Releaseビルド成功。Small・日本語の実画面で32pxの二つのボタンが収まり、「5分後に再通知」で窓が隠れることを確認。短縮せず5分待ち、同じ窓IDに同じ予定一枚が戻ることと、カード内の「閉じる」で終了することを確認した。English・Largeの実画面、再起動復元、音は今回の確認対象外。

もうあるか：Tauriの非同期ランタイムと、依存済みTokioのsleepを利用する。独自の待機スレッドや画面側の別タイマーは作らない。[Tauri spawn](https://docs.rs/tauri/latest/tauri/async_runtime/fn.spawn.html)、[Tokio sleep](https://docs.rs/tokio/latest/tokio/time/fn.sleep.html)。

保存・復元の隔離実画面（2026-11-10）：再通知を選んで予約を保存し、期限前に通常起動し直して待機を維持。同じ通知窓に「15:00 歯医者の予約」が戻ること、カード内の「閉じる」で消え、保存が空になり、再起動しても通知が復活しないことを確認した。別の期限切れ保存fixtureでも、プレビュー引数なしの起動直後に同じカードが表示された。通常の実ユーザーデータとWPF版は変更せず、確認用Tauriは終了し、Computer Useも確認ごとに終了した。English・Large、実Google、音の移植はこの確認に含まない。

## 一般配布前のGoogle準備

2026-11-10、[Google公式のSensitive scope verification](https://developers.google.com/identity/protocols/oauth2/production-readiness/sensitive-scope-verification)を確認。既存WPFの要求権限はカレンダー一覧と予定の読取りのみ。一般向けOAuth配布では、ブランド確認・要求権限の審査に備え、アプリ紹介ページ、プライバシーポリシー、ドメイン所有確認、各権限の必要理由、英語の認可フローと機能を示す動画を準備する。個人・開発テスト利用には審査の例外があるが、一般配布の完成条件とは分ける。

紹介ページとプライバシーポリシーを日英で公開し、サイトの所有確認・承認済みドメイン登録・Google側のホームページとポリシーURL保存を完了した。Googleの公開状態はテスト中で、審査は未提出。[紹介ページ](https://tinmoon-label-site.pages.dev/works/alter-genesis/)、[プライバシーポリシー](https://tinmoon-label-site.pages.dev/works/alter-genesis/privacy/)。ポリシーはGoogle連携を備えたWindows検証版の扱いを説明しており、TauriのGoogle移植後に再照合する。

## 責任の分け方

- Rust: 設定と通知状態の保存、Google接続、予定取得、時刻計算、鳴り直し、トレイ、単一起動、自動起動ショートカット。
- Svelte: 設定画面と通知カードの描画、利用者の明示的な操作。
- 両者の境界: Rustが状態を持ち、画面へイベントを送る。画面は操作結果をRustへ返し、独自の保存状態を重複して持たない。

Google OAuth情報と認証トークンはソース管理へ入れない。一般配布用のGoogle設定、署名、プライバシーポリシーは別の公開準備として扱う。
